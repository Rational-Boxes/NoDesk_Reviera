Scripting and automation

Every tool in Reviera runs a registered command. The same commands are available in the command shell, in Lua scripts and plugins, and to AI agents over the Model Context Protocol (MCP), with the same undo, warnings and checks as the ribbon.

Commands

A command has a name of the form domain.verb (wall.create, door.place, roof.set_eaves), JSON arguments described by a JSON Schema, and a permission level. The help pages name the commands behind each tool in code. To list and explain them:

  • registry.list lists every command with its summary;
  • registry.describe gives one command's description and argument schema.

Lengths in commands and scripts are in metres, whatever the model's display units.

The command shell

From a terminal, reviera shell model.ifc opens a model and reads one command per line: the command's name, then its arguments as JSON.

reviera shell model.ifc
> :commands wall
> level.list
> level.create {"elevation": 3.0}
> edit.undo {"steps": 2}
> file.save
> :quit

:commands [prefix] lists the commands (those starting with the prefix), :docs lists the open documents and :quit leaves. The shell is a session of its own: it does not drive an open window.

Lua scripts

Scripts are LuaJIT. In a script, reviera.<domain>.<verb>{...} runs a command: reviera.wall.create{...} is wall.create. The arguments are a table, as the command's JSON arguments, and the result comes back as a table or value. reviera.call(name, args) runs any command by name. A failed command raises a Lua error whose message starts with the error code, so pcall can catch it.

-- title: Two walls
-- description: An L of two 5 m walls on the first level.
local level = reviera.level.list()[1].id
local function wall(a, b)
  return reviera.wall.create{
    curve = { line = { start = a, ["end"] = b } },
    base_level = level, top_constraint = { unconnected = 3.0 },
  }
end
wall({0, 0}, {5, 0})
wall({5, 0}, {5, 5})
print("Two walls")
  • A whole run is one undo step, and it is rolled back entirely if the script fails.
  • print (or reviera.print) and reviera.ui.message report to the user.
  • Scripts run with the safe standard libraries: no ffi, debug, io or process control.
  • The sample models are built by scripts: house.lua, manor.lua and the others beside the samples are complete examples.

Commands: script.run (Lua code or a file).

Asking for input: forms

reviera.ui.form{title, message, fields} asks the user for values and returns a table of them by field key, or nil when the user cancels. In the window it shows as a dialog in the model's units, checking each value and asking again until it is valid.

local t = reviera.ui.form{
  title = "Tower",
  message = "A round tower.",
  fields = {
    { key = "radius", label = "Radius", type = "length", default = 2.5, min = 1, max = 15,
      help = "To the walls' centrelines" },
    { key = "sides", label = "Sides", type = "integer", default = 16, min = 6 },
    { key = "roof", label = "Top", type = "choice", choices = { "Cone", "Dome" } },
  },
}
if t == nil then return end

Field types are length (metres; the user may type units), number, integer, bool (a checkbox), choice and text. Runs without a window (the shell, MCP, tests) take the values from the call's answers and the defaults.

Plugins

A plugin is either a folder with a plugin.lua that returns a table with title, description and a run function, or a single .lua file with -- title: and -- description: lines at the top. Reviera finds them:

  • built in: the Castle Turret plugin, which builds a round tower with a cone, dome or battlements and arrow slits from a form;
  • in your script library: ~/.config/reviera/plugins on Linux, %APPDATA%\Reviera\plugins on Windows (or REVIERA_LIBRARY);
  • in the folders listed in REVIERA_PLUGINS.

Commands: plugin.list, plugin.run, script.import, script.remove.

The Scripts menu

Run Script…Runs a .lua file on the active model, as one undo step. Run Script…
Import into Library…Copies a script file or a plugin folder into your script library, so it is listed in this menu.
Manage Library…Lists the known scripts with their descriptions, to run, remove or import them. Built-in scripts cannot be removed.
The scriptsEvery known script and plugin, by title: choose one to run it. The Observatory sample's turret was made with Scripts › Castle Turret.

MCP for AI agents

reviera --mcp-stdio runs Reviera as an MCP server on standard input and output. Every command is a tool, grouped into toolsets (core, modeling, documentation, families, materials, project_setup, io, collaboration, analysis, scripting, admin) that the agent enables as it needs them. Agents also get discovery tools, query_elements and get_element, undo and redo, undo groups, a preview and confirmation for destructive changes, and the model's documents and elements as resources.

To connect Claude Code to a model:

claude mcp add reviera -- /path/to/reviera --mcp-stdio --permission model_edit /path/to/model.ifc
PermissionWhat the agent may do
read_only (the default)Read the model; nothing changes.
model_editEdit the model. Files are written only to the output folder, and destructive changes need confirming.
full_scriptingEvery command.

--toolsets a,b enables toolsets from the start. The MCP server is a session of its own, without a window: it opens the file it is given, and the agent saves it with file.save. The agent's changes are recorded in the history as made by an agent.

Not yet available: MCP over HTTP with tokens, subscriptions, prompts, an execute_lua tool and view images.
