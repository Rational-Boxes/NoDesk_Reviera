Types and parameters

Most elements have a type that holds the values they share, such as a wall's width or a door's size. Each element also has its own parameters. Both are edited in the Properties palette and saved as ordinary IFC types and property sets.

Types

Walls, doors, windows, floors, ceilings, roofs, stairs, railings and grids have types. In Properties, the Type row of a selected wall, door, window, floor, roof or grid shows its type:

  • Choose another type from the list to change the selected elements' type.
  • Duplicate Type… (the last entry in the list) copies the current type under a new name and gives it to the selection. Change the new type's values afterwards.
  • Type Name renames the type.
  • The rows under Type Parameters (n walls) are the type's values. Changing one changes every element of that type: the heading says how many there are.

With a tool running and nothing selected, the Type row chooses the type the tool places: start the Wall, Door, Window or Grid tool, then pick the type in Properties before clicking in the view.

To make a new door type

  1. Place a door (the first door makes the default type) and select it.
  2. In Properties › Type, choose Duplicate Type… and type a name, for example Arched Door 1000 x 2400.
  3. Under Type Parameters, set Width 1000, Height 2400 and Shape Round Top.

The Manor and Storefront samples are built from types made this way. type.list, type.duplicate, type.rename, type.set_param, element.set_type

Instance and type parameters

Properties list every parameter of the selection, grouped (Identity Data, Constraints, Dimensions and so on). Type parameters are marked as such; editing one changes the type. An instance parameter belongs to the selected element alone. When several elements are selected, an edit applies to all of them.

Some values are computed and read-only, such as a floor's area and volume or a stair's actual riser height; they are shown greyed.

Parameters are written to IFC property sets, so other IFC tools see them. param.list, param.get, param.set, param.set_many, param.clear, param.definition

Project parameters and property sets

Project parameters (your own parameters, bound to categories as type or instance parameters) and direct property set edits are available as commands today; there is no dialog for them yet. Run them from the command shell or a script: param.project.add, param.project.modify, param.project.remove, param.set_ifc_home, pset.set, pset.remove. Once added, a project parameter shows in Properties like any other.

Global parameters

Global parameters are named project-wide values, such as a corridor width or a door sill height, that drive dimensions and element parameters. Open Global Parameters (G L, Manage › Settings) to make, edit, copy and delete them. A value can be typed with its unit (1800 mm) or worked out by a formula over other globals, such as CorridorWidth * 2 + 300 mm. Reviera refuses a formula that adds a length to a plain number, and a formula that ends up depending on itself.

To make a dimension keep a global's value, select a dimension with one segment and choose Label with Global. The first thing it measures from stays put and the second moves, now and whenever the global changes. To drive a parameter, select the elements and choose Associate Global, then pick the parameter (for doors and windows, Sill Height) and a global of the same type. Changing a global updates everything it drives in one step, so a single Undo puts it all back.

A reporting global reads its value from the one dimension it labels, so other globals' formulas can use a measured distance. Select Elements selects everything a global drives. Deleting a global leaves what it drove at its current value.

Parameter libraries

A parameter library is a file of shared parameter definitions (.rplib.json), each identified by a GUID so that every project using it means the same parameter. Open Parameter Libraries (Manage › Settings) to open or make libraries. Definitions… shows a library's definitions. There you can add one, edit its name, tooltip, labels and IFC home, or deprecate it. A definition's data type never changes and definitions are never removed, so files stay compatible. Changes are written to the library file straight away, not to the project.

Add to Project… binds a definition to categories as a shared parameter. The project keeps a full copy, so it opens and schedules the same on a machine without the library. If the project already has that GUID under another name, choose whether to keep the project's or update it from the library. Import Legacy… reads an older shared-parameter text file and keeps its GUIDs. Export IFC Templates… writes the library as IFC property set templates for other tools.

Classification and keynotes

Classification Systems (Manage › Settings) loads a classification table into the project, such as Uniclass, OmniClass, MasterFormat or a national system. Use a CSV file with a code, parent code and title on each line, or an IFC file that contains a classification. Reviera doesn't come with any tables, because they belong to their publishers. Select types or elements and choose Classify, pick the system, search for the code and choose it. Each element has at most one code per system. When you save, the codes are written as standard IFC classification references, so other tools can read them.

Load Keynotes reads a keynote file: a text file with a key, a text and a parent key on each line, separated by tabs. Keep it beside the project and the project remembers it by name, so it still works when the folder moves. keynotes.reload reads it again after you edit it.
