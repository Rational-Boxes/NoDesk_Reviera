BIMserver projects

An Open Source BIMserver keeps a shared model and its revisions. Reviera can publish a project to one, open a server project as a working copy on your computer, and check your changes in as new revisions.

Servers and logging in

File › BIMserver… lists your servers. Add Server… asks for a name and the server's address, for example https://bim.example.org (where the server's /json is). Plain http:// is accepted only for a server on this computer. Reviera asks the server for its version before adding it, then asks you to log in: with your user name and password, or with the user token shown on your BIMserver user page. Log Out ends the session and can forget the stored password; Remove Server removes the server and its password (your working copies stay).

Opening a server project

Choose a project, then Open Latest, or choose a revision and Open Revision. Reviera downloads it into a working copy on this computer and opens it; the title bar shows the project and the revision it is based on. Save (Ctrl+S) saves the working copy only: nothing reaches the server until you check in. Opening a project you already have a working copy of opens that copy with your work in it, never overwriting it, and says when the server has newer revisions.

Publishing a project

With a project open from a file, choose the server project and Publish Current Project…: Reviera checks it in as that project's first revision and the open project becomes its working copy. A project that already has revisions asks you to confirm a new revision over them. The schemas must match (IFC4 or IFC2X3). Creating projects on the server needs the rights the server gives (by default only administrators make new top-level projects).

Checking in

Check In… saves the working copy and uploads it as a new revision, with your comment. If someone else checked in a newer revision since yours was downloaded, Reviera refuses rather than overwrite their work; merging their changes into yours comes with Synchronise.

How passwords are kept

Your password or user token is kept in the system keychain (or, where there is none, only until Reviera closes), never in a Reviera file or a project. Server addresses and user names are your own settings, not part of any project. AI agents connected to Reviera can list projects and use a session you started, but can never log in with a password or remove a server.
