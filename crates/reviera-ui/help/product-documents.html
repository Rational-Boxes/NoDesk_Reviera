Material Documents

A material's product documents, such as its EPD (Environmental Product Declaration), HPD (Health Product Declaration), datasheets and certificates, can live in one FileEngine folder that the model points to. Reviera can read values out of those documents, each with the words it was read from. You decide which values go into the model.

Linking a material to its folder

Open File › Material Documents…. The list shows the project's materials (the ones that walls, floors, ceilings and roofs use) and any that are already documented. Choose a material, then Link Folder…, and browse to the product's folder on FileEngine (see Models on FileEngine to connect and sign in).

The model keeps the folder by its FileEngine identifier, so the link still works when the folder is renamed or moved. Unlink removes the link; the values read from the documents stay unless you also forget them.

Document types

Each document in the folder has a type: EPD, HPD, specification, certification, installation, O&M, warranty, SDS, drawing or other. Reviera reads an EPD's values only from documents marked EPD, and an HPD's values only from documents marked HPD, so that a figure is never taken from the wrong kind of document. Choose a document and Set Type… to mark it; the type is kept on FileEngine, where other people and tools see it too.

Reading values from the documents

Choose Read EPD or Read HPD. FileEngine's conversion service reads each document of that type whole, and gives back these values:

  • EPD: manufacturer, product, EPD number, programme operator, declared unit, GWP for modules A1–A3 including biogenic carbon and, where the EPD gives it, excluding it (kg CO₂e per declared unit), and the date it is valid until.
  • HPD: the HPD identifier, the HPD standard version, the MasterFormat classification, the content threshold (ppm), the highest-concern hazard scores, the VOC emissions certificate, and the dates it was published and is valid until.

Each value is shown with the words it was read from (the quote) and the document's version. A value the service could not back with a quote is listed as not found: nothing is guessed. Reading takes about half a minute a document. Reading the same version again is answered at once from the service's cache.

Accepting values

Nothing is written until you accept. Tick the values you want and choose Apply. They go onto the material in one step, which Undo takes back. Each value remembers the document, version and reading it came from.

  • Also write to the folder puts the values in the folder's FileEngine metadata too (epd.number, epd.gwp_a1a3, hpd.valid_until, …), so that FileEngine can list and search products by them.
  • When two documents disagree on a value, Reviera asks which one to take.

An EPD's carbon

With Use the GWP for embodied carbon ticked, the EPD's GWP A1–A3 becomes the material's emission factor for embodied carbon, in a library named Product EPDs. Reviera converts the declared unit: an EPD declared per 1,000 ft² of board at 126 kg CO₂e gives 1.356 kg CO₂e per m². It reads m², ft², m³, ft³, yd³, kg, tonnes, lb and pieces; any other unit is refused with the reason.

In the model and in IFC

An IFC4 file carries, for each documented material:

  • the folder as an IfcDocumentReference (its address and identifier), tied to the IfcMaterial;
  • the values as material properties, Reviera_EPD and Reviera_HPD, each with the printed unit and the documents they came from.

When the model itself is saved to FileEngine, its metadata lists the documented materials and their values (reviera.products).

Limits and what to check

  • The service reads the documents' text. A scanned page with no text layer is listed as skipped (no text); check it by hand.
  • An EPD often gives several GWP figures (with or without biogenic carbon, by different methods). Reviera asks for GWP-total including biogenic carbon (IPCC AR6, or EN 15804+A2); check the quote to see which one was read.
  • Your FileEngine key has a usage allowance (requests a minute, tokens a day). The dialog shows it, and warns before it runs out.

Scripts and agents

Everything above is a command in the docs domain: docs.link, docs.list, docs.set_doc_type, docs.extract, docs.apply_extracted, docs.materials, docs.field_sets and docs.usage. Lua scripts and AI agents (MCP) can use them, acting as you. The field sets are JSON Schemas in schemas/extract/.
