Models on FileEngine

FileEngine (Proxima File Vault) keeps your organisation's files in folders, with every saved version kept. Reviera can open a model from FileEngine, save it back as a new version with Ctrl+S, and show or restore any earlier version. FileEngine decides who may read and write each folder.

Connecting and signing in

Open File › Open From FileEngine… and choose Add Connection…. Give your organisation's FileEngine address, for example https://acme.proximafilevault.com, and a name if you like.

Reviera then asks you to Sign In with a credential: a key (fesk_…) and its secret (fesks_…). Generate one with the api scope in FileEngine's account settings and paste both in. You can also paste the whole key:secret into the Key box. Tick Remember to keep it in the system keychain, and you won't be asked again.

Sign Out ends the session and can also forget the credential. Remove deletes the connection and its credential; the models on this computer stay.

Opening a model

Choose a connection to see its folders. Double-click a folder to go into it, and use Up to go back. Choose a model (.ifc) and Open.

Reviera downloads the model into a working copy on this computer and opens it like any file, with undo and crash recovery. The title bar shows the model's name and (FileEngine). The Here column marks the models you already have a working copy of.

If your working copy holds work that hasn't been uploaded yet, opening the model again opens that work. It is never overwritten, and Reviera tells you when someone has saved a newer version.

Saving

Save (Ctrl+S) saves the model on this computer, then uploads it to FileEngine as a new version. To add a comment to the version, use File › Save to FileEngine…. The comment is shown in the version history.

To put a project that is a file on this computer into FileEngine, use Save to FileEngine…. Choose the folder (New Folder… makes one), give the model a name and choose Save Here. From then on, Ctrl+S saves new versions of it.

Each save also records the model's IFC schema, its project GlobalId and its level names on the file, so FileEngine can list and search models by them.

If the server can't be reached, the save is kept on this computer and the title bar says not uploaded. The next save sends it.

When someone else saved first

Before uploading, Reviera checks that the newest version on FileEngine is still the one you opened. If a colleague has saved since then, nothing is uploaded: your work stays saved on this computer, and Reviera tells you who saved and when. You can then choose one of these:

  • Save as a Copy Beside It: your work becomes a new model in the same folder, named after you (hall (ann's copy).ifc for ann@acme.com saving hall.ifc). Their model stays as it is.
  • Overwrite: your work becomes the newest version. Theirs stays in the version history.
  • Open Theirs Read-Only: their version opens beside yours, so you can compare them.

Reviera never merges the two silently.

Version history

File › FileEngine Version History… lists every version of the open model, newest first: when it was saved (UTC), who saved it, its comment, and which one is open.

  • Open Read-Only opens a version beside the model, to look at or compare.
  • Restore… makes a version the newest again. FileEngine saves it as a new version, so nothing is lost, and the model reopens at it. Save or discard your changes first.

Read-only models

A model in a folder you may not write opens read-only. So does a past version. To keep your changes to one, use Save to FileEngine… into a folder you can write, or File › Save As to a file on this computer.

How the credential is kept

The credential is kept in the system keychain, or until Reviera closes if you didn't tick Remember. It is never written in a model, a settings file or a log, and nothing in Reviera shows it again. Reviera exchanges it for a sign-in token that lasts a few minutes and renews itself.

You can revoke the credential in FileEngine at any time. Reviera then asks you to sign in again.

Scripts and agents

Everything above is a command in the fileengine domain, such as fileengine.browse, fileengine.open, fileengine.save and fileengine.versions. Lua scripts and AI agents (MCP) can use them, acting as you. file.open accepts fileengine://<connection>/<uid>, and file.save_as accepts fileengine://<connection>/<folder uid>/<name>.ifc.

Agents can't give a credential or remove a connection. They can only use one you have stored.
