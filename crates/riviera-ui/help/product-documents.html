Material Documents

A material's product documents, such as its EPD (Environmental Product Declaration), HPD (Health Product Declaration), datasheets and certificates, can live in one folder that the model points to: a folder on this computer, or one on FileEngine. Everything works with a local folder. FileEngine adds sharing, reading values out of the documents for you (each with the words it was read from) and publishing reports. You decide which values go into the model.

Linking a material to its folder

Open File › Material Documents…. The list shows the project's materials (the ones that walls, floors, ceilings and roofs use) and any that are already documented. Choose a material, then Link Folder…. When a FileEngine connection is set up, Riviera asks whether the folder is on this computer or on FileEngine; otherwise it goes straight to choosing a folder on this computer. For FileEngine, browse to the product's folder (see Models on FileEngine to connect and sign in).

A local folder's files are its documents (hidden files are left out). Each one's version is the time it was last changed, in UTC, written as FileEngine writes versions (20261031_142233.000). Open opens the chosen document in its usual application. A FileEngine folder is kept by its identifier, so the link still works when the folder is renamed or moved. Unlink removes the link; the values read from the documents stay unless you also forget them.

Document types

Each document in the folder has a type: EPD, HPD, specification, certification, installation, O&M, warranty, SDS, drawing or other. Riviera reads an EPD's values only from documents marked EPD, and an HPD's values only from documents marked HPD, so that a figure is never taken from the wrong kind of document. Choose a document and Set Type… to mark it. On FileEngine the type is kept with the file, where other people and tools see it too; for a local folder it is kept in the model.

Entering values by hand

Enter Values… asks for the field set (EPD or HPD), then shows its fields. Type in the values the document gives and leave the rest blank, choose the document they came from, and choose Enter. Numbers and dates are checked before anything is written. The values go onto the material in one step, with that document as their source, just as values read by FileEngine do. This is the way for a local folder, and works for a FileEngine folder too.

Reading values from the documents

This needs the documents on FileEngine; for a local folder, the buttons are greyed out. Choose Read EPD or Read HPD. FileEngine's conversion service reads each document of that type whole, and gives back these values:

  • EPD: manufacturer, product, EPD number, programme operator, declared unit, GWP for modules A1–A3 including biogenic carbon and, where the EPD gives it, excluding it (kg CO₂e per declared unit), and the date it is valid until.
  • HPD: the HPD identifier, the HPD standard version, the MasterFormat classification, the content threshold (ppm), the highest-concern hazard scores, the VOC emissions certificate, and the dates it was published and is valid until.

Each value is shown with the words it was read from (the quote) and the document's version. A value the service could not back with a quote is listed as not found: nothing is guessed. Reading takes about half a minute a document. Reading the same version again is answered at once from the service's cache.

The first time you read with a field set on a server, Riviera publishes it there as an extraction prompt set named riviera.epd or riviera.hpd. Your administrator doesn't need to set anything up. The server's own extraction tools and folder automation can then use the same definition. If someone who manages extraction on the server has taken the set over, Riviera reads with their version, and the review says so. A PDF read this way also gets a marked-up copy beside it on FileEngine, with each value's words highlighted. Choose Open Marked-up PDF in the review to see it: it opens the copy for the selected value's document in your PDF viewer, and the review stays as you left it. A server without prompt sets is asked the old way, with the same results.

Accepting values

Nothing is written until you accept. Tick the values you want and choose Apply. They go onto the material in one step, which Undo takes back. Each value remembers the document, version and reading it came from.

  • Also write to the folder puts the values in the folder's FileEngine metadata too (epd.number, epd.gwp_a1a3, hpd.valid_until, …), so that FileEngine can list and search products by them.
  • When two documents disagree on a value, Riviera asks which one to take.

An EPD's carbon

With Use the GWP for embodied carbon ticked, the EPD's GWP A1–A3 becomes the material's emission factor for embodied carbon, in a library named Product EPDs. Riviera converts the declared unit: an EPD declared per 1,000 ft² of board at 126 kg CO₂e gives 1.356 kg CO₂e per m². It reads m², ft², m³, ft³, yd³, kg, tonnes, lb and pieces; any other unit is refused with the reason.

In the model and in IFC

An IFC4 file carries, for each documented material:

  • the folder as an IfcDocumentReference (its address and identifier, or a file:/// address and its path for a local folder), tied to the IfcMaterial;
  • the values as material properties, Riviera_EPD and Riviera_HPD, each with the printed unit and the documents they came from.

When the model itself is saved to FileEngine, its metadata lists the documented materials and their values (riviera.products).

Publishing local documents to FileEngine

A project documented in local folders can move to FileEngine once a connection is set up. File › Publish Local Documents to FileEngine… is offered while the project has a local documents folder and a connection exists; Publish to FileEngine… in the Material Documents dialog does the same for the chosen material's folder. Choose the FileEngine folder to publish into. Riviera makes a folder of the same name in it (or uses the one there), uploads each document (a new version of a file already there) and sets the types you gave.

Riviera then asks whether to update the model's references. With yes, the materials point to the folder on FileEngine and their values to the uploaded files, in one step that Undo takes back; save the model to keep it. With no, the model keeps pointing at the local folder, and the documents are on FileEngine for others to read.

Limits and what to check

  • The service reads the documents' text. A scanned page with no text layer is listed as skipped (no text); check it by hand.
  • An EPD often gives several GWP figures (with or without biogenic carbon, by different methods). Riviera asks for GWP-total including biogenic carbon (IPCC AR6, or EN 15804+A2); check the quote to see which one was read.
  • Your FileEngine key has a usage allowance (requests a minute, tokens a day). The dialog shows it, and warns before it runs out.

Scripts and agents

Everything above is a command in the docs domain: docs.link, docs.list, docs.set_doc_type, docs.document_path, docs.enter_values, docs.extract, docs.apply_extracted, docs.materials, docs.field_sets, docs.publish_field_sets, docs.usage, docs.local_collections and docs.publish_local. Lua scripts and AI agents (MCP) can use them, acting as you. The field sets are JSON Schemas in schemas/extract/.
