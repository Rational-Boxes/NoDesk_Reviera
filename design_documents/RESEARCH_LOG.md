---

## 1. Purpose

This log confirms that **every piece of information in the Reviera design documents comes from publicly available sources**. No proprietary, confidential, leaked, NDA-covered or otherwise non-public information was used.

For each fact in the specification, the log records:
- **where** it came from: a public URL in the Source Register (§5)
- **when** it was retrieved, and **how**: a dated session entry (§4)
- **who** saw which material (§7)

So anyone can trace a statement in the specification back to a public source and check that the source was openly available on the date it was used.

The specification is functional. It describes *what* the reference application does from the user's point of view, in our own words.

## 2. Clean-Room Protocol

| # | Rule | Status |
|---|------|--------|
| P1 | Use only publicly accessible sources: vendor help docs, public blogs, published tutorials, public forums, press and release notes. | In force |
| P2 | No decompiling, disassembling, debugging or reverse-engineering of Revit binaries, file formats or network traffic. | In force |
| P3 | No installing or running Revit, and no use of a Revit licence, for this research (this avoids taking on EULA obligations). | In force |
| P4 | No confidential, leaked, NDA-covered or paywalled-and-redistributed material. No current or former Autodesk employee's non-public knowledge. | In force |
| P5 | No copying of Autodesk source code, API implementation code, icons, artwork, fonts, family/template content (.rfa/.rte/.rft) or help text into Reviera deliverables. | In force |
| P6 | The specification describes behaviour and functional requirements in our own words. Short quotations are kept to a minimum and attributed. | In force |
| P7 | Screenshots are kept as **internal reference only**, with a recorded source URL. They are not to be shipped, redistributed, or traced or copied into Reviera's UI assets (see §6). | In force |
| P8 | Every research session gets a dated entry in §4. Every source gets an entry in §5. | In force |
| P9 | Recommended: people who implement Reviera work from the specification, not from the raw screenshots or vendor docs. Any exposure to those should be noted in §7. | Recommended |

**Public-availability test for a source.** A source qualifies only if all of these are true:
- anyone could reach it without logging in, or with only a free public account
- it was not behind an NDA, beta programme, partner portal or employee-only system
- it was not leaked, scraped from a private system, or redistributed without authorisation

Any source that fails this test is rejected. Rejections are noted in the session entry.

### 2026-10-12 — Session 1: Research kickoff

- **Actions:**
  - Created folders `design_documents/research/` and `design_documents/screenshots/{ui,architecture,structure_mep,documentation,platform}`.
  - Started five parallel automated research agents (Claude Code subagents), one per area. They use public web search and web fetch only.
  - Instructions to the agents: prefer Autodesk's public online help (help.autodesk.com), public Autodesk blogs, public API reference sites and reputable tutorials; record a source URL for every screenshot; list sources at the end of each research file.
- **Methods used:** public web search, HTTP fetch of public pages, HTTP download of publicly served images.
- **Methods not used:** no Revit installation; no binary or file-format reverse engineering; no authenticated or paywalled content; no confidential material.
- **Open items:** collect the agents' source lists into §5 and screenshot records into §6 when they finish; write the consolidated specification.

### 2026-10-12 — Session 1 (continued): Research complete, registers compiled

- **Research outputs:** `research/01`–`05`, about 81,000 words in total, plus 142 screenshots.
- **How the research agents worked:**
  - They read public Autodesk Help (2026 and 2027 editions) and compared the two editions' topic lists to find version changes.
  - They also used public reseller and tutorial blogs, and public GitHub repositories.
  - Where a vendor page refused automated access (HTTP 403), the agents did **not** try to get around the block. They used other public sources or search-result summaries instead, and marked those items in the research files as "unverified" or "practitioner knowledge".
- **Verification:**
  - Every downloaded image was checked with `file` to confirm it is a real image.
  - All 580 URLs found in the research files were re-checked without authentication (see §5).
  - Three URLs were excluded because they were directory roots or a template placeholder, not sources.
- **Spec drafting:** `spec/00_conventions.md` sets the clean-room writing rules (own words, no copied text or assets, traceability). Five subagents were started to write the specification chapters from the research files.

### 2026-10-12 — Session 1 (continued): Specification drafted and integrated

- **Inputs used.** Only `research/01`–`05`, the internal screenshots, `TECH_STACK.md` and the owner's design decisions. No new external sources were added, except one check of the public BIMserver source (`ServiceInterface.java` on GitHub) to confirm the Extended Data API.
- **Chapters.**
  - Five writer subagents produced the specification chapters under `spec/00_conventions.md`: own words, no copied text, files or assets, and a `Ref:` link from each feature back to its research section.
  - The lead wrote Chapter 0 (overview) and Chapter 2a (the RXD format).
  - The lead then integrated everything: renumbered collaboration as Chapter 6 (keeping research references intact), reconciled RXD names into one registry, aligned the IFC export command names, and generated Appendix A.
- **Clean-room text check.** Every chapter was compared with the research files for word-for-word runs of 12 or more words.
  - **Result:** 152 runs, the longest 38 words. All of them are lists of interface labels, parameter names, category names, enumerated option values or shortcut lists. These are functional names, which `00_conventions.md` §1 allows. No copied prose was found.
  - **Brand names:** "Revit" and "Autodesk" appear only in Reference/Ref lines and in the title disclaimer.
- **Output.**
  - `Revit_Application_Specification.md`: about 21,400 lines, 622 numbered requirements (276 P0, 215 P1, 125 P2, 3 P3) and 1,590 commands.
  - It is assembled by `tools/build_spec.py` from `spec/*.md`.
